# LoRA для классификации русских новостных заголовков

Дообучение `Qwen2.5-1.5B-Instruct` через LoRA на 3000 заголовках и сравнение с промптингом и TF-IDF на одной тестовой выборке. Хотел проверить, при каком объёме разметки LoRA имеет смысл по сравнению с более дешёвыми вариантами.

Основные результаты (тест 1200 заголовков):

- LoRA на 3000 примерах: accuracy 0.885 [0.867; 0.902], невалидных ответов нет.
- Это на 19.6 п.п. выше few-shot той же модели и на 7.5 п.п. выше TF-IDF + логрегрессии на тех же 3000 примерах (p < 0.001 в обоих случаях).
- TF-IDF + логрегрессия на всех 36 000 примерах даёт 0.877. Разница с LoRA +0.008 [−0.010; +0.027], p = 0.19, то есть статистически не отличается.

Получается, LoRA выигрывает при небольшой разметке. Если размеченных данных много, классический метод даёт сопоставимое качество и не требует GPU.

## Задача и данные

- Задача: отнести заголовок к одной из 6 рубрик (спорт, происшествия, политика, наука, культура, экономика).
- Датасет: [`ai-forever/headline-classification`](https://huggingface.co/datasets/ai-forever/headline-classification) из ruMTEB, лицензия MIT. Train / validation / test: 36 000 / 12 000 / 12 000, классы сбалансированы.
- Модель: `Qwen/Qwen2.5-1.5B-Instruct`, Google Colab, Tesla T4 (16 ГБ).
- Версии: torch 2.11, transformers 5.17, peft 0.21, scikit-learn 1.6.

## Порядок эксперимента

1. Проверка утечки между train и test.
2. Фиксация выборок.
3. Бейзлайны до обучения.
4. Обучение LoRA.
5. Сравнение всех вариантов на одном тесте.

### Утечка train → test

Датасет собран из корпуса парафраз, поэтому один новостной повод может встречаться и в train, и в test в разных формулировках. Для каждого тестового заголовка я искал ближайший заголовок из train по косинусу TF-IDF на символьных 3–5-граммах.

| Косинус к ближайшему из train | Доля test | У соседа та же рубрика |
|---|---|---|
| точное совпадение после нормализации | 3 из 12 000 | – |
| ≥ 0.5 | 25.9% | 93.2% |
| ≥ 0.8 | 2.4% | 98.3% |

Порог 0.8 выбрал, просмотрев пары вручную: начиная с него это практически всегда один и тот же повод. Такие заголовки убрал из теста, осталось 11 710 (97.6%).

Символьный TF-IDF находит только близкие по написанию формулировки, пересказ другими словами он не поймает.

### Выборки

Индексы сохранены в `results/splits.json`, seed 42.

- test: 1200 заголовков из очищенного теста, по 200 на рубрику. Все варианты оцениваются на них, поэтому можно сравнивать попарно.
- train: 3000 из train, по 500 на рубрику. Одни и те же для LoRA и для TF-IDF.
- validation: 300, по 50 на рубрику, только для контроля лосса.
- Примеры для few-shot: по одному на рубрику из train вне обучающих 3000. Первый случайный пример оказался неправильно размеченным, поэтому для каждой рубрики вывел 6 случайных кандидатов и выбрал однозначный вручную.

### Метрики

- Основная метрика: accuracy, классы сбалансированы. Macro-F1 привожу для справки: на синтетическом примере он завышался при невалидных ответах, потому что такой ответ не попадает ни в один класс и не снижает precision.
- 95% доверительные интервалы считал бутстрепом по тестовым примерам.
- Варианты сравнивал парным бутстрепом: на каждой итерации обе модели оцениваются на одной и той же перевыборке, считается интервал разности и p.
- Ответ, который не удалось сопоставить ни с одной рубрикой, считается ошибкой.
- Строгий разбор ответа требует названия рубрики. Мягкий разбор (синонимы, «технологии» → наука, английские названия) я добавил после просмотра ответов модели, поэтому он только для диагностики: показывает, сколько few-shot теряет на формате ответа.

## Результаты

| Вариант | Accuracy | 95% CI | Невалидных | Macro-F1 |
|---|---|---|---|---|
| Qwen zero-shot | 0.408 | [0.381; 0.435] | 24.2% | 0.416 |
| Qwen zero-shot, мягкий разбор | 0.503 | [0.475; 0.532] | 10.7% | 0.493 |
| Qwen few-shot (6 примеров) | 0.689 | [0.663; 0.716] | 8.6% | 0.697 |
| Qwen few-shot, мягкий разбор | 0.763 | [0.738; 0.787] | 0.9% | 0.763 |
| TF-IDF + LogReg, 3000 | 0.810 | [0.787; 0.833] | – | 0.810 |
| TF-IDF + LogReg, 36 000 | 0.877 | [0.858; 0.896] | – | 0.877 |
| Qwen + LoRA, 3000 | 0.885 | [0.867; 0.902] | 0% | 0.885 |

Парный бутстреп, разность accuracy:

| Сравнение | Разность | 95% CI | p |
|---|---|---|---|
| LoRA − few-shot | +0.196 | [+0.170; +0.222] | < 0.001 |
| LoRA − few-shot (мягкий разбор) | +0.123 | [+0.100; +0.145] | < 0.001 |
| LoRA − TF-IDF (3000) | +0.075 | [+0.054; +0.096] | < 0.001 |
| LoRA − TF-IDF (36 000) | +0.008 | [−0.010; +0.027] | 0.188 |
| few-shot − zero-shot | +0.281 | [+0.251; +0.309] | < 0.001 |

С мягким разбором few-shot всё равно отстаёт от LoRA на 12 п.п., так что дело не только в формате ответа.

## Обучение LoRA

| Параметр | Значение |
|---|---|
| r / alpha / dropout | 16 / 32 / 0.05 |
| Модули | `q_proj`, `k_proj`, `v_proj`, `o_proj`, все 28 слоёв |
| Обучаемых параметров | 4 358 144 из 1 548 072 448 (0.28%) |
| Эпох | 2 (376 шагов) |
| Батч | 4, накопление градиента 4 (эффективный 16) |
| Learning rate | 2e-4, cosine, 11 шагов warmup |
| Точность | база в fp16, адаптер в fp32 |
| Время | 12.3 мин на T4 |

Число параметров: LoRA добавляет к матрице `in × out` матрицы `in × r` и `r × out`, это `r · (in + out)` параметров. Скрытый размер Qwen2.5-1.5B 1536, из-за GQA `k_proj` и `v_proj` выдают 256 (2 KV-головы по 128). Получается 16 · 3072 = 49 152 для q и o, 16 · 1792 = 28 672 для k и v, 155 648 на слой и 4 358 144 на 28 слоёв.

Обучающий пример состоит из того же промпта, что в zero-shot, и ответа: название рубрики и `<|im_end|>`, чтобы модель училась останавливаться. Лосс считается только по ответу, токены промпта в labels заменены на `-100`. Длина примера: медиана 204 токена, максимум 261.

| Эпоха | train loss (конец эпохи) | val loss |
|---|---|---|
| 1 | 0.111 | 0.126 |
| 2 | 0.065 | 0.110 |

Val loss снижался обе эпохи.

Проблемы, с которыми столкнулся:

- Импорт peft падал с `ImportError` из-за предустановленного в Colab torchao. Помогло `pip uninstall -y torchao` и перезапуск среды.
- В transformers 5 убрали `warmup_ratio`, заменил на `warmup_steps=11`. `torch_dtype` заменён на `dtype`.
- CUDA OOM на T4. Память заканчивалась из-за логитов: батч 16 × ~260 токенов × словарь ~152k во fp32 занимают около 2.5 ГБ. Перешёл на микробатч 4 с накоплением градиента 4.

## Ошибки

LoRA ошиблась в 138 заголовках из 1200. Матрица ошибок (строки — разметка, столбцы — ответ):

| | спорт | происш. | политика | наука | культура | экономика |
|---|---|---|---|---|---|---|
| спорт | 195 | 1 | 1 | 0 | 3 | 0 |
| происшествия | 1 | 177 | 12 | 3 | 2 | 5 |
| политика | 1 | 5 | 176 | 2 | 8 | 8 |
| наука | 4 | 4 | 2 | 177 | 6 | 7 |
| культура | 17 | 2 | 6 | 6 | 166 | 3 |
| экономика | 1 | 3 | 12 | 10 | 3 | 171 |

Чаще всего модель отвечала «спорт» на заголовки с меткой «культура» (17 случаев). Я их просмотрел: примерно 12 из них про спорт («ПСВ на выезде разобрался с „Твенте“», «Южноафриканский пловец выиграл золото с мировым рекордом»), то есть ошибка в разметке. Около 3 спорных (Пол Маккартни на открытии Олимпиады), явных ошибок модели около двух («Выступить в Туле Расторгуеву помешала возрастная аритмия», «„Таганка“ осталась без Любимова»).

Ещё разметил вручную 40 случайных ошибок:

| Категория | Кол-во |
|---|---|
| ошибка в разметке | 7 |
| явная ошибка модели | 6 |
| спорный заголовок, подходят обе рубрики | 27 |

Явных ошибок модели около 15% (6 из 40, интервал грубо 6–30%). Остальное приходится на шум разметки и пограничные темы: экономика и политика (санкции, бюджет), происшествия и политика, экономика и наука. Для дальнейшего роста метрики, скорее всего, полезнее почистить разметку, чем брать модель больше.

## Забывание

Задал три общих вопроса с выключенным и включённым адаптером, без количественной оценки.

- Объяснение инфляции нормальное в обоих случаях.
- Просьбу перевести фразу на английский модель с адаптером выполнила, но ответила по-английски на русский вопрос.
- На просьбу назвать три столицы с адаптером появились лишние приписки: «Париж — Франция (Питер)», «Берлин — Германия (Берн)».

Адаптер ухудшает ответы на общие вопросы, поэтому его стоит подключать только для этой задачи. Peft позволяет держать одну базовую модель и включать адаптер по необходимости.

## Выводы

1. Few-shot заметно лучше zero-shot (+28 п.п.), но для модели 1.5B он уступает даже TF-IDF на 3000 примерах.
2. LoRA на 3000 примерах лучше промптинга и TF-IDF на тех же данных и всегда отвечает в нужном формате.
3. TF-IDF + логрегрессия на 36 000 примерах выходит на тот же уровень, при этом обучается и работает на CPU. Для простой классификации с большой разметкой я бы выбрал её.
4. Заметная часть оставшихся ошибок связана с разметкой.

## Ограничения

- Один датасет, одна модель, один запуск обучения: разброс между сидами не измерен.
- Гиперпараметры LoRA не подбирались, взяты стандартные стартовые значения.
- Промптинг проверялся только на той же модели 1.5B. Модель крупнее в few-shot, вероятно, показала бы больше.
- Проверка утечки находит только близкие формулировки.
- Примеры для few-shot выбраны вручную, мягкий разбор добавлен после просмотра ответов.
- Ошибки размечал один человек.
- Проверка забывания — три вопроса.

## Запуск

1. Открыть `lora_headlines.ipynb` в Google Colab с GPU T4.
2. Выполнить первую ячейку (удаляет torchao, ставит peft) и перезапустить среду.
3. Выполнить остальные ячейки по порядку. Датасет и модель скачиваются с Hugging Face.

На T4: проверка утечки ~40 с, zero-shot ~1 мин, few-shot ~2 мин, обучение ~12 мин, оценка LoRA ~1.5 мин.
